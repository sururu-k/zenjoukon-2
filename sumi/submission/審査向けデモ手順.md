# Sumi 審査向けデモ手順

Sumiは、情報を渡す範囲を先に決め、その範囲を超えないよう処理するための試作です。ここでは架空のデータを使い、アンケート、文書の共有、合計の証明、エージェントの操作を順に確認します。確認操作は模擬であり、実際のデータの保存や外部送信は行いません。

## デモを始める

Node.jsと依存パッケージが必要です。リポジトリの `sumi` フォルダーで、初回のみ `npm ci` を実行し、次を実行します。

```sh
npm run demo -- --pause
```

各場面で止まります。Enterキーを押すと次の場面に進みます。止めずに実行する場合は `npm run demo` を使います。架空データはスクリプトに含まれます。

## 90秒で見せる順番

| 時間 | 場面 | 確認すること |
| --- | --- | --- |
| 0〜10秒 | 目的 | 「見ない」という約束に加え、相手に渡す情報を減らす仕組みを作る。 |
| 10〜27秒 | アンケート | ２件では集計を出さず、３件では２件・１件の合計を表示する。１端末の模擬であり、個別回答の秘密は保証しない。 |
| 27〜40秒 | Write | 文書の本文案に内部メモを含めない。 |
| 40〜58秒 | Gate | メールアドレスを加工し、確認前の書き出しと文書変更後の書き出しを拒否する。確認はデモ内で模擬する。 |
| 58〜73秒 | Prove | ４件の数値について合計60の証明を検証し、合計を61に変えると検証が失敗する。 |
| 73〜90秒 | Agentと限界 | 未確認の文書の要約や外部送信の提案を拒否する。機能全体や端末全体の漏洩不在を証明したものではない。 |

同じ流れの [90秒紹介映像](Sumi_90秒デモ.mp4) は、自動デモの実行結果を読みやすく再配置した無音の映像です。ブラウザの画面操作を記録した動画ではありません。生成にはmacOSのヒラギノフォント、PythonのPillow、Node.js、FFmpegが必要です。`python3 scripts/create-demo-video.py` でデモを実行してから映像を作り直せます。

## 実演結果の読み方

アンケートは２つのシェアを同じ端末で扱うため、本物の回答収集には使えません。３件は提出数であり、異なる３人の回答とは確認できません。担当者の分離、鍵の配送、本人確認、少数集計からの推測対策は別途必要です。

Writeの内部メモは本文生成に渡しませんが、本文欄へ機密を入力した場合まで防ぐものではありません。Gateの自動加工は検出漏れがあるため、共有版全体の確認が必要です。Proveが示すのはコミット済み数値と公開された合計の関係であり、入力が事実であることは示しません。

# Sumi：共通基盤から3つの製品へ

Sumiは、AIの提案、利用者の確認、実行の認可を分けた基盤を、文書の作成・共有・証明に応用した作品です。アンケートは入力例の一つとして残し、利用の中心を文書ソフトへ広げています。3製品はブラウザで動く試作であり、OS全体の保存を監視する常駐ソフトではありません。

| 製品 | 解決する課題 | 独立した操作の流れ |
| --- | --- | --- |
| Sumi Write | 内部の事情をメモしながら文書を作ると、本文やAI入力へ混ぜてしまう | 本文用メモと内部メモを分離 → 定型またはローカルAIで文章案 → 採用・編集 → 加工した共有版を確認 → 認可して書き出す |
| Sumi Gate | 既存書類を、内容や行き先を確認せず配布してしまう | TXT・CSV・貼り付け → 候補の検出と加工 → 出力先と現行版の確認 → 認可してコピー・署名付き保存 |
| Sumi Prove | 個々の数値を渡さずに合計の関係を検証したいが、証明の設計が分かりにくい | 用途を定型またはAIで整理 → 対応する形式か検査 → 開示内容を確認 → 端末内でZK証明を生成・検証 → 暗号化した証明を交換 |

3つは `authorization.js`、`information-flow.js`、`workspace.js`、`browser-effects.js`、`crypto.js` を共有します。異なるのは入力と利用目的、提案を作る処理、確認画面です。製品ごとに同じ認可コードをコピーして保守する構成にはしていません。

## 「AIで補助するZKP」の役割

ProveのAIは、用途ラベルを整理し、許可された形式のプランを提案します。この版が実行するのは `sumi-committed-sum-v1` のみです。AIが返す任意のプログラムや証明回路は実行しません。プランのキー、開示する項目、証明しない項目を検査し、利用者の確認後に暗号コードを呼び出します。

元の数値はAIの要求に含めません。数値の入力と証明計算は端末内で行います。公開されるのは件数・合計・用途ラベル・コミットメント・証明です。証明するのはコミットした値の合計の一致であり、自然言語の用途ラベル全体が真であること、入力の真実性、身元、範囲、情報漏洩の不在ではありません。

WriteのAIには文書の種類・題名・本文用のメモを渡します。内部メモ欄は読みません。ただし、本文用メモへ利用者が機密を書いた場合や、内部メモを本文へ手動で貼り付けた場合は、この分離だけでは防げません。書き出す前に全文を確認します。

## 提出時の説明案

作品名の案は「Sumi — AIの提案を、検証してから使う文書と証明の基盤」です。

「一つの信頼基盤を作り、その再利用性を3つの異なる利用場面で示した」と説明します。3つの画面の紹介に加え、内部メモや数値がAI入力に入らないテスト、文書の変更による承認失効、改変した証明の検証失敗を実演します。

2026年11月8日に確認した[全国大会の応募要項](https://zenjyocon.jp/contest2026)と[愛知県大会の応募要項](https://zenjyocon.jp/contest2026/aichi)では、同じ代表者による複数作品の応募は不可で、ソースコード・動画などの補足資料を提出できます。提出案は共通基盤を1作品とし、3製品を応用例・補足資料として説明する形です。別々に3件応募できるという意味ではありません。応募の操作は行っていません。

## デモと検証

1. Writeで架空のメモから定型文を作り、内部メモ欄の内容が本文へ入らないことを示します。共有版を確認・認可して保存し、下書きは内部メモを含めて暗号化保存・復元します。
2. Gateで架空の活動報告を加工し、出力先を選んで公開を許可します。その後に原文を変更し、コピー・保存が無効になることを示します。
3. Proveで「各班の人数の合計」の定型プランを作ります。12・18・9・21から合計60の証明を作り、個別値を含めない証明を別の利用者が検証します。用途や合計を改変すると検証に失敗します。

ローカルAIはOllamaの起動・モデル・Origin許可が必要です。未接続時は定型モードとして明示し、AIが生成したようには表示しません。共通AIクライアントの同意・モデルの検査・版変更・不正応答の扱いは模擬応答で自動テストしています。実モデルの品質やブラウザ操作の評価とは分けて扱います。

共通基盤のLeanモデルは11定理を検査し、認可と経路の選択を各2,560条件でJavaScriptと照合します。3製品のUI・JavaScript全体の正しさや情報漏洩全体の不在を証明したものではありません。前提と未証明部分は `ASSURANCE.md` と公開する検証レポートを参照してください。

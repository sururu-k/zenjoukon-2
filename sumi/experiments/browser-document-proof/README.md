# ブラウザでの文書不在証明：実験

架空の短い文書と４語の公開ポリシーを使い、ブラウザ内で Noir の witness とゼロ知識証明を生成し、同じブラウザで検証する実験です。証明に記載された公開条件と、検証者が別途確認した条件を照合します。文書と秘密の開封情報を使い、コミットメントが同じ文書に対応するか確認する処理もあります。共有メモリの分離ヘッダーがない環境でも動くか確かめます。既存のローカル実装の回路をそのままコンパイルします。

```sh
cd sumi/experiments/browser-document-proof
npm ci
npx playwright install chromium
SUMI_NARGO=/path/to/nargo npm test
```

Noir 1.0.0 が必要です。既存の Chromium を使う場合は `SUMI_CHROMIUM` に実行ファイルのパスを指定できます。テストは架空文書からの証明、公開入力の改変の拒否、不正な witness 入力の拒否を調べます。証明内の公開条件と期待条件の両方を同じ偽の値に置き換え、単純な条件照合を通過させた上で暗号検証が拒否することも確認します。禁止語を含む入力ではコミットメントを作り直した上で、回路が拒否することを確認します。回路の禁止語判定は `scripts/noir-document-v2-demo.mjs` でも確認します。

初回は証明用ライブラリが Aztec の CRS 配布先から公開パラメータを GET します。テストでは通信先とメソッドを検査しますが、パッケージや配布先の安全性を保証するものではありません。端末のメモリを数百 MB 使用します。これは研究用の実験です。証明対象は最大512バイトの文書に、指定した最大４語（各16バイト）がバイト単位で完全一致しないことです。個人情報全体が含まれない保証ではありません。

開封情報は秘密の salt を含みます。証明と一緒に公開せず、安全な別経路で必要な相手にだけ渡してください。文書の対応を証明するだけなら証明書への添付は不要です。公開条件そのものの真正性は保証しないため、検証者は信頼できる経路で条件を確認する必要があります。

## 操作画面

同じ実験を、文書を入力して証明を保存し、別の画面で検証する操作として試せます。保存した証明・期待条件・開封情報のJSONはそれぞれ対応するファイル選択欄から読み込めます。

```sh
SUMI_NARGO=/path/to/nargo npm run build
cd dist
python3 -m http.server 4188 --bind 127.0.0.1
```

`http://127.0.0.1:4188/` を開きます。ネットワークアクセスは公開パラメータ取得に必要です。`npm run test:ui` は別々のブラウザ画面で証明の作成・検証と条件の差し替え拒否を試します。GitHub Actions はテスト後、静的ファイルを GitHub Pages の `/document-proof/` に配置します。画面の証明形式は、この実験の `sumi-document-browser-v1` です。ローカル版 CLI の証明ファイルとの相互運用は確認していません。

公開画面では証明の検証後に、文書と非公開の開封情報を使って、検証済みコミットメントとの対応を確かめられます。照合には、文書と開封情報を確認者に渡す必要があります。

禁止語の初期値は共通の架空学校設定 [`school-policy.example.json`](../../src/school-policy.example.json) から読み込みます。共通の検証コードで形式・版・項目・値を確認しますが、値は編集可能であり、学校の承認や真正性を保証しません。検証者は期待条件を別途確認してください。

画面の「学校別の共通設定ファイル」から、同じ形式のJSONを端末内で読み込むこともできます。ファイル全体を形式検査し、文書証明には禁止語のみを反映します。選択時に以前の作成結果は消えます。不正なファイルは拒否し、以前の禁止語を維持します。読み込んだ設定の発行元や内容は利用者が別途確認してください。選択したファイルを学校点検や他の画面に自動配布する機能ではありません。

画面テストは、１つの架空の共通設定を学校点検・エージェント・文書証明にそれぞれ渡します。点検の設定案を取得し、エージェントの加工と証明の公開条件に設定の禁止語が使われることを確認します。自動配布や発行元認証のテストではありません。

# ブラウザでの文書不在証明：実験

架空の短い文書と４語の公開ポリシーを使い、ブラウザ内で Noir の witness とゼロ知識証明を生成し、同じブラウザで検証する実験です。証明に記載された公開条件と、検証者が別途確認した条件を照合します。文書と秘密の開封情報を使い、コミットメントが同じ文書に対応するか確認する処理もあります。共有メモリの分離ヘッダーがない環境でも動くか確かめます。既存のローカル実装の回路をそのままコンパイルします。

```sh
cd sumi/experiments/browser-document-proof
npm ci
npx playwright install chromium
SUMI_NARGO=/path/to/nargo npm test
```

Noir 1.0.0 が必要です。既存の Chromium を使う場合は `SUMI_CHROMIUM` に実行ファイルのパスを指定できます。テストは架空文書からの証明、公開入力の改変の拒否、不正な witness 入力の拒否を調べます。禁止語を含む入力ではコミットメントを作り直した上で、回路が拒否することを確認します。回路の禁止語判定は `scripts/noir-document-v2-demo.mjs` でも確認します。

初回は証明用ライブラリが Aztec の CRS 配布先から公開パラメータを GET します。テストでは通信先とメソッドを検査しますが、パッケージや配布先の安全性を保証するものではありません。端末のメモリを数百 MB 使用します。これは開発者向け実験で、公開アプリではありません。証明対象は最大512バイトの文書に、指定した最大４語（各16バイト）がバイト単位で完全一致しないことです。個人情報全体が含まれない保証ではありません。

開封情報は秘密の salt を含みます。証明と一緒に公開せず、安全な別経路で必要な相手にだけ渡してください。文書の対応を証明するだけなら証明書への添付は不要です。公開条件そのものの真正性は保証しないため、検証者は信頼できる経路で条件を確認する必要があります。

## 操作画面

同じ実験を、文書を入力して証明を保存し、別の画面で検証する操作として試せます。

```sh
SUMI_NARGO=/path/to/nargo npm run build
cd dist
python3 -m http.server 4188 --bind 127.0.0.1
```

`http://127.0.0.1:4188/` を開きます。ネットワークアクセスは公開パラメータ取得に必要です。`npm run test:ui` は別々のブラウザ画面で証明の作成・検証と条件の差し替え拒否を試します。生成された静的ファイルを公開する仕組みや、審査員向け公開 URL はまだ用意していません。画面の証明形式は、この実験の `sumi-document-browser-v1` です。ローカル版 CLI の証明ファイルとの相互運用は確認していません。

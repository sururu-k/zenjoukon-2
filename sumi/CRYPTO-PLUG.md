# 暗号を組み合わせる下位レイヤ

ホワイトボードにある「暗号文での計算」「結果の検証」「複数主体による鍵の保全」を、それぞれ独立した信頼境界として扱います。用途ごとに全部を作り直さず、必要な境界を組み合わせるための部品です。

今回追加した部品は、既存の BFV 暗号化集計の鍵バックアップを2-of-3で分散し、復元前に各担当者が自分のシェアと署名済みコミットメントの整合性を確認するものです。`npm run demo:fhe-verifiable-backup` で架空データを使った集計、シェア検証、１人での拒否、２人での復元を試せます。学校の集計にも、企業の集計にも同じ部品を利用できます。

実装はランダムな復元用秘密を Ristretto のスカラー体で Shamir 分散し、Feldman 方式の群要素によるコミットメントで各シェアを検証します。シェアと元の鍵のバックアップは別々に暗号化され、独立したECDSA署名の組でマニフェストを認証します。期待するマニフェストハッシュ、鍵ID、署名検証鍵は、配布物とは別の信頼できる経路で得る必要があります。

この構成には明確な前提があります。

- 秘密分散するのはBFV秘密鍵を保護する復元用秘密です。２人がそろうと１つのプロセス内で秘密とBFV鍵が復元されます。閾値BFV復号ではありません。
- コミットメントは離散対数の困難性に依存し、情報理論的な秘匿ではありません。発行者の不正や鍵の取違えをすべて防ぐものでもありません。暗号化済みのBFV鍵とコミットメントの対応は、復元に成功するまで確認できません。
- 各担当者の端末、パスワード、信頼鍵の配布、バックアップの可用性を信頼します。実装は未監査で、JavaScript上の秘密値を確実に消去できません。
- シェアの正当性の検証は、FHE計算が正しいことのZK証明ではありません。ホワイトボードが描く Verifiable FHE は、暗号文・計算内容・結果を結ぶ証明を別途必要とし、この部品だけでは実現しません。

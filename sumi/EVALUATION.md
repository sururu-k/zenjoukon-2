# 架空データを使ったマスクの検査

## 学校の課題と、この評価の位置付け

[文部科学省「教育情報セキュリティポリシーハンドブック」（令和７年３月）](https://www.mext.go.jp/content/20250325-mxt_jogai01-100003157_4.pdf#page=19)の20ページは、児童生徒がアクセスできる場所への個人情報・成績情報の誤保管や、成績一覧がある紙の裏面を渡したことによる漏洩などを、教育現場の事故事例として挙げています。同資料は研修やルールの浸透も重視しています。

この資料は学校での情報管理に課題がある根拠ですが、Sumiを使えばこれらの事故を防げるという実証ではありません。Sumiの文書証明が調べるのは入力したテキストの指定語との完全一致で、保存先の権限設定、紙の裏面、画像や入力していないファイルは確認できません。実際の教職員への聞き取りや学校環境での効果測定も、まだ行っていません。

`npm run evaluate:masking` は、`evaluation/masking-cases.json` にある架空の文書を加工し、指定した文字列がそのまま残っているかを確認します。氏名やメールなどの例に加え、健康情報や生徒番号のように、現在の検出が苦手な例も含めています。対照文は、加工の必要がないと仮定した短い例です。

この検査は開発中に用意した少数の例であり、実際の学校文書に対する検出率ではありません。文字列が消えた場合でも、一部の文字や文脈から推測される可能性があります。逆に、対照文が変わらなくても、他の文章で不要な加工が起きないとは言えません。正式な評価には、収集と利用に同意を得たデータまたは適切に作られた独立データ、評価基準、見落としと過剰加工の両方の検討が必要です。

非公開にしたい語句を利用者が追加する例も含みます。これは事前に何を隠すか分かっている場合の補助であり、自動検出の性能には含めずに解釈します。結果は確認の補助で、マスク後の全文を人が確認する必要があります。

## 再実行した結果

2026年11月9日に、リポジトリ内の例を使って次のように確認しました。ここで「消えた」は、例ごとに指定した文字列が加工後の文章に完全一致で残っていないという意味です。安全に匿名化できたことまでは示しません。

| 確認した例 | 結果 |
| --- | --- |
| 自動検出のみで、指定文字列が消えた例 | 12例中8例 |
| 自分で隠す語を指定して、指定文字列が消えた例 | 2例中2例 |
| 加工不要と仮定した対照文が変化しなかった例 | 3例中3例 |

自動検出の４つの残存例は、ラベルのない氏名、健康情報、生徒番号、家庭事情です。たとえば「架空花子さんが参加します。」という例では、指定した氏名が加工後にも残りました。利用者が語句を指定した２例は、あらかじめ隠す対象を知っている条件なので、自動検出の結果に合算しません。

例は開発側が選んだ探索用データであり、独立した評価用データではありません。この比率を学校文書での検出率として扱うことはできません。また、指定文字列が消えていても部分的な情報や文脈から推測される可能性があり、未検出の情報を「ない」と判断する根拠にもなりません。

`sumi` ディレクトリで次を実行すると、件数と各例の結果をJSONで表示します。入力例は [`evaluation/masking-cases.json`](evaluation/masking-cases.json)、集計処理は [`scripts/evaluate-masking.mjs`](scripts/evaluate-masking.mjs) です。変更後は集計結果も変わり得ます。

```sh
npm run evaluate:masking
```

## テスト例と文書全体の比較

「２つの例に通った」ことと「文書全体の条件」を区別するため、意図的に**先頭32バイトだけ**を探す不完全な検査を対照に作りました。特定の既存製品を模したものではありません。禁止語を「山田」とした架空文書で、同じ入力を先頭だけの検査・通常の全文検索・Noir回路に与えます。

| 架空文書 | 先頭だけの検査 | 全文に完全一致 | 回路の入力 |
| --- | --- | --- | --- |
| 指定語なし（最初の例） | 未検出 | なし | 成立 |
| 先頭に指定語（最初の例） | 検出 | あり | 拒否 |
| 32バイト以降に指定語 | 未検出 | あり | 拒否 |
| 512バイト文書の末尾に指定語 | 未検出 | あり | 拒否 |
| 「山」と「田」の間に文字を挿入 | 未検出 | なし | 成立 |

最初の２例だけでは、不完全な検査も期待した結果になります。追加した２例では見逃します。一方、最後の例は指定語とバイト単位で完全一致しないので、回路も受理します。この表は選んだ例の結果であり、一般の検査ソフトの性能比較や、現実の学校文書に対する検出率ではありません。

全文を完全一致検索すること自体は、ゼロ知識証明がなくても可能です。この試作でZKを使う目的は、**原文を渡さずに、指定した条件に対する証明を検証できるようにすること**です。指定語の選び漏れや表記ゆれへの対応は別の課題です。回路と実装の安全性は外部監査を受けていません。

Noir 1.0.0とBarretenberg 6.0.0を用意して、次で再実行します。各文書のコミットメントをその文書から作り直し、回路が入力を受け入れるかを確かめます。指定語なしの１例については実際に証明を生成し、別コマンドで検証します。拒否された例については証明生成ではなく、回路の証明入力の作成が失敗したことを確認しています。

```sh
cd sumi
SUMI_NARGO=/path/to/nargo SUMI_BB=/path/to/bb node scripts/compare-rule-proof.mjs
```

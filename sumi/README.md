# Sumi — 学校の共有前チェック

探究アンケートの原文を端末内で加工し、共有する範囲と出力先を確認するWebアプリです。数値を使う「秘匿集計」では、ゼロ知識証明・MPC・BFV準同型暗号・差分プライバシーを試せます。ライブラリとWASMはビルドに同梱し、CDNから読み込みません。

## 起動

開発サーバーと自動テストにはNode.js 22以降を使います。

```sh
npm ci
npm run dev
```

`http://127.0.0.1:4173` を開きます。初期表示は6件の架空の通学アンケートです。ポートは `SUMI_PORT` で指定できます。開発サーバーは起動時に形式検証とビルドを実行します。編集後は再起動してください。

```sh
npm test
npm run verify:formal
npm run build
```

形式検証とビルドには、`formal/lean-toolchain` に指定したLean 4.34.1を使います。`lean` がPATH上にある環境で実行してください。ビルドは形式検証が成功した場合だけ `dist/` を生成します。HTTPSの静的ホスティングにも配置できます。

## 実装済みの機能

- テキスト貼り付け、UTF-8のTXT・CSV読み込み。1行を1件の回答として扱います。
- 氏名、住所、年齢、学校、クラス、役職、部活動、連絡先などのルール検出。
- 教員・生徒・校外発表の加工条件と、居住地・年齢・学年の粒度選択。
- 加工前後の確認、候補ごとの変更、追加指定語、確認後のコピー。
- 加工後の文章だけを使う通学時間・交通手段・キーワード集計。根拠の回答IDを表示。
- ローカルOllamaの任意接続、構造化応答による補助検出、加工後の文章の要約。
- Web Cryptoによる暗号化下書きの保存・復元と、署名付き共有ファイルの保存・検証。
- 保存・コピー・AI送信の認可判定。文書の版・加工条件・出力先に結びついた確認と、変更時の失効。
- 認可・平文出力の非干渉を示す形式モデルと、版ごとの検証結果・前提を示す保証範囲ページ。

## 保存・配布の認可

[Nyxis](https://github.com/NyxFoundation/nyxis) の、判断の正本となるルールと実行処理を分ける考え方を取り入れています。Nyxis本体、Cedar、認証サーバーは組み込まず、このアプリで必要な操作に絞った独自の認可層を実装しています。

| 経路 | 実行に必要な条件 |
| --- | --- |
| クリップボードへのコピー | 公開用の加工条件、その経路の選択、現行版の利用者確認 |
| 配布用ファイルの保存 | 公開用の加工条件、その経路の選択、現行版の利用者確認 |
| 原文を含む下書きの保存 | 暗号化の完了、処理中に文書が変更されていないこと |
| ローカルAIへの送信 | 明示的な利用操作、ループバック接続先、現行版との一致 |
| 未登録の保存・配布先 | 拒否 |

「配布用ファイル」か「クリップボード」を選び、文章全体・加工条件・出力先を確認すると、選んだ経路を使えます。文書・条件・出力先の変更や確認の取り消しで承認は失効します。署名・暗号化の待機中に変更された場合も、実際の書き出しの前に拒否します。

- `src/authorization.js`：副作用を持たない認可ルール。未登録・不明・不完全な入力は拒否します。
- `src/workspace.js`：文書のコピー、版、確認、署名鍵を画面の状態から分けて保持し、実行直前に検査します。
- `src/information-flow.js`：公開を許可した値・暗号文・秘密の入力を別のフィールドから取り出し、出力先を選びます。
- `src/browser-effects.js`：クリップボード、ダウンロード、AIへのHTTP送信をまとめた実行処理です。
- `formal/Policy.lean`：認可判定の6定理と、任意の長さの有限操作列における平文の非干渉など5定理です。

Leanでは「不明な区分・古い版・未登録の出力先は拒否」「平文出力には公開区分と確認が必要」「下書きには暗号化が必要」「AI送信には端末内の接続先と同意が必要」に加え、許可済みの要求列と公開を許可した値が同じなら、秘密状態を変えても外部向けの平文の列は変わらないことを検査します。ビルド時には、4区分×4操作×5経路×32通りのフラグ、計2,560条件で、認可判定と出力経路がそれぞれ実際のJavaScriptと一致することも確認します。

証明の対象は認可と情報流のモデルです。JavaScript全体、機密分類の正しさ、検出の網羅性、利用者の身元、暗号ライブラリ・ブラウザ・OS全体の安全性は証明していません。手動コピー、別アプリでの保存、悪意あるJavaScriptによる操作も制御対象に含みません。保存フォルダの権限検査や学校の組織権限との連携は未実装です。すべての出力経路の扱いと残る前提は [ASSURANCE.md](ASSURANCE.md)、公開する版の検証結果は `assurance.html` と `assurance/report.json` を参照してください。

## データの扱い

原文・加工結果・置換の対応はブラウザのメモリ内に保持します。LocalStorage、アクセス解析、外部フォント、外部AIへの送信は使用しません。閉じる・再読み込みをすると下書きは失われます。

Ollamaの補助検出を明示的に有効にすると、原文を利用者が選んだループバック上のOllamaへ送ります。接続先は `localhost`、`127.0.0.1`、`[::1]` のみで、クラウドモデルと判定したものは除外します。接続先を信頼できる端末内プロセスとして運用することが前提です。Ollama側でこのサイトのOriginを許可する必要があり、ブラウザのローカルネットワーク接続制限にも依存します。

接続方法は [Ollama公式FAQ](https://docs.ollama.com/faq)、応答形式は [Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs) を参照してください。アプリがモデルをダウンロードすることはありません。モデル未接続時はルール検出で動作します。

## 暗号機能の範囲

下書きの暗号化にはAES-256-GCM、12バイトのランダムIV、16バイトのランダムsalt、PBKDF2-SHA256を310,000回適用した鍵を使います。v2はUTF-8のJSONと長さを1MiBの固定長フレーム内に置いて暗号化し、平文の長さをファイル長へ出しません。入力はUTF-8で1MiB未満に制限します。旧v1は読み込み互換を維持します。パスフレーズは保存しません。

共有ファイルは、加工後の文章・加工条件・確認状態に加え、加工後の文章のハッシュ・公開版のダイジェスト・出力経路・認可ルールの版をECDSA P-256 / SHA-256で署名します。原文全体、加工前後の対応表、原文のハッシュ、元ファイル名、内部の編集回数と承認用ハッシュは添付しません。「原文を残す」と選んだ候補がある場合、平文の共有ファイル保存とコピーは認可されません。暗号化下書きとして保存できます。

署名鍵はタブのセッションごとに生成し、秘密鍵は非抽出可能なCryptoKeyとしてメモリ内に保持します。学校や教員の身元を証明する鍵ではありません。同梱された公開鍵だけで検証した場合は「送信者の身元は未確認」と表示します。送信者から別経路で受け取った鍵指紋を入力すると、署名と鍵指紋の両方を照合します。

署名検証は内容の正しさや匿名性を保証しません。秘匿集計の方式・使い方・前提条件は [PRIVACY_COMPUTATION.md](PRIVACY_COMPUTATION.md) に記載しています。TEEと、ブートストラップを使う無制限のFHE計算は未実装です。

## 検出・評価の限界

氏名の検出は項目ラベルや一部の表記に基づきます。自由文の氏名、未登録の地名、複数情報を組み合わせた推測などの網羅的な検出はできません。候補が0件でも安全を意味しません。追加指定語と利用者の確認を併用する設計です。

ローカルAIの出力は、原文に存在する文字列と許可した種類に制限し、置換内容はアプリのルールから決定します。AIの要約は未確認として表示し、共有ファイルへ自動では追加しません。

48件の自動テストに、50件の架空の定型回答、粒度の切替、通学時間の保持・非公開、CSV、外部接続先の拒否、暗号化復元、誤パスフレーズ、署名と鍵指紋、共有内容の変更検知を含めています。認可については、画面を経由しない呼び出しの拒否、承認後の文書差し替え、署名・暗号化中の変更、署名された認可情報、AIの接続条件を検査しています。秘匿集計ではZKの改変拒否、MPCの復元と重複拒否、ランダム化回答の全8条件、実際のBFV暗号文の集計・復号を検査しています。実際の学校文書での検出精度を示す評価ではありません。

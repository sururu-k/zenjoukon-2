# 見えないアンケート

生徒会が意見を集めたいとき、回答が個別に見られることを気にせず答えられたらどうでしょうか。昼休みの図書室についての架空の問いで、個々の回答をそのまま集めずに合計する方法を試します。生徒会や委員会での利用を想定していますが、本音を書きやすくなるかの聞き取りや効果測定はまだ行っていません。

## 実際に動く部分

`survey-demo.html` は回答画面と集計画面を切り替えます。二択の回答をそれぞれ２つのシェアに分け、各シェアを合計してから全体を復元します。３件未満では集計できず、集計確定後は同じ画面での追加回答を止めます。３件の架空回答を自動で入れる操作もあります。端末では `npm run demo` で同じ計算を試せます。

秘密分散による合算、３件未満の拒否、確定後の追加拒否は自動テストで確認しています。別の端末版 `school-study.mjs` は、暗号化したシェアのファイルを別々の担当者へ渡して合算する例です。

集計担当の処理は `secure/survey.js` に分けています。各担当は自分宛てのシェアだけを受け取り、同じ識別子の重複や、３件未満の合算を拒否します。端末版では `school-study.mjs survey-vote`、`survey-aggregate`、`survey-result` で、この処理を暗号化ファイルの交換に使えます。各端末は必要なファイルとパスフレーズだけを受け取る運用です。送信、相手の認証、パスフレーズの配送、集計の公開回数の管理は行いません。

## 安全性の前提と残る課題

ブラウザの体験版は、AとBのシェアを両方とも同じ端末のメモリに持ちます。画面上で個別回答を表示しない設計ですが、端末の管理者や開発者ツールから個別回答を守る保証はありません。実際の回答を収集してはいけません。

実運用ではシェアを異なる管理主体へ送り、互いに共謀しない前提を守る仕組みが必要です。３件は提出の組数であり、異なる３人の回答とは確認できません。１人の重複回答、虚偽の入力、公開済みの合計と別の集計との差からの推測も防げません。最低件数だけで匿名性を保証することはできません。

不正な回答の影響は `node scripts/survey-adversary.mjs` で再現できます。２件の正規の「反対」と、細工して数値２を入れた１件を合わせると、３件中「賛成２・反対１」として受理されます。合計が件数以内でも、各回答が０か１だったとは限りません。端末が正しく回答を作るという前提を外すには、各回答の有効性と両シェアの対応を、回答を明かさず検証するプロトコルが必要です。既存の合計に関するZK証明は、この条件を証明していません。

別途 `src/secure/bit-proof.js` に、コミットメントの値が０か１であることを示すOR証明の実験を追加しています。参考は [Cramer・Damgård・Schoenmakersの部分知識証明](https://ir.cwi.nl/pub/1456/1456D.pdf) です。０と１の証明の検証と、証明・用途を変更した場合の拒否をテストします。ただし、この証明は既存の回答シェアに結び付けていません。したがって上記の攻撃は引き続き成功し、この実験をアンケートの防御としては使えません。方式の安全性や実装は外部監査を受けていません。

さらに `src/secure/verified-survey.js` では、別形式の研究用プロトコルとして、２つのシェアそれぞれのコミットメントと、その合計が０または１である証明を結び付けています。各担当は自分のシェアが対応するコミットメントに一致するかと、共通の証明を検証します。集計IDや提出ID、コミットメントを証明に結び付け、異なる提出組の合計を拒否します。改変や別の回答の証明の使い回しを拒否するテストがあります。

この研究用形式も現在のブラウザ版・HTTP版には接続していません。また、担当者による合算結果の改ざん、本人確認、重複投票、通信相手の認証、共謀、集計結果からの推測を防ぐものではなく、プロトコルの安全性の証明や外部監査もありません。既存形式とは計算する数の範囲が異なり、互換ではありません。

端末版は回答者もA・B両方のパスフレーズを知る方式です。自分以外の両方のファイルを入手した人は、その提出の回答を復元し得ます。提出者は別々の経路で担当者にファイルを渡し、他の提出者の両シェアを入手できないようにする必要があります。この方式は鍵配布や受信者制限を保証せず、実データの収集を安全に運用できる段階ではありません。

Leanで検査している認可・情報流モデルやエージェントの実行条件は、このアンケート全体の安全性を証明していません。公開する範囲と前提を先に定義し、分離された実行環境と本人確認、集計の公開制限を実装・検証することが次の課題です。

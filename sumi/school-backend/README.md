# 学校向けバックエンドの正本案

Nyxisの構造を、学校の文書・役割・所属・許可操作に対応づけるためのCedarスキーマとポリシーの下書きです。スキーマに操作の効果を明示し、ポリシーを認可の正本とし、ハンドラは認可層だけを通して読み書きする構成を目指します。

対象を文書に限定せず、生徒・教員・管理者・AIエージェントが扱う連絡、共有、アカウント、端末、データ分析、設備の運用を対象として設計します。実装済みの端末用コマンドは、共通の5項目について自己申告に基づく点検と設定案を生成します。利用者がJSONポリシーを書く必要はありません。

```sh
node scripts/school-audit.mjs draft
node scripts/school-audit.mjs check school-backend/observations.example.json
node scripts/products-demo.mjs
```

`draft` は設定案と物理チェックリストをJSONで出力します。`check` は報告された値を判定し、未確認または不適合がある場合は終了コード2を返します。どちらも設定の適用や実環境の自動収集は行いません。

`products-demo.mjs` は架空データを使い、Writeの文書作成、Gateの加工、Proveの合計証明をブラウザなしで実行します。3製品の書き出し判定には同じ `sumi-egress-v1` の認可ルールを使い、未確認の書き出しを拒否します。学校向け5項目の点検は別の共通モデルであり、現時点ではこの認可ルールに結び付いていません。デモは実データの保存や配布を行いません。

現段階では**下書き**です。Cedarパーサによる検証、認証済み主体の取得、データベースの現在値の取得、ハンドラの効果制限、HTTP・ファイルストレージ・監査ログ・実行時の接続、Leanによるアプリケーション全体の認可安全性の検査は未実装です。実際の学校データを扱える状態ではありません。

Nyxisの構造をそのまま再現するには、これらを一体として実装し、信頼する前提と証明が対象とする範囲を確認する必要があります。ブラウザ上の自己申告や、ポリシー文字列を置いただけの状態を「検証済みのファイルサーバ」とは扱いません。

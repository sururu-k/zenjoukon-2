# 情報流の保証範囲

Sumiは、認可されていないアプリの出力を止め、承認して公開した平文と秘密の原文を分ける設計です。この文書は、すべての出力経路を検証対象として整理し、証明・実装検査・信頼する前提を対応づけます。**実環境全体の情報漏洩が不可能になったという証明はありません。**

Write・Gate・Proveは同じ認可基盤を使います。Writeは内部メモを定型の本文組み立て・AI要求から除外し、Proveは数値をAI要求へ含めません。これらのJavaScriptの分離は自動テストで確認します。AIが作った案や自然言語の用途全体が正しいと証明するものではありません。各製品の役割と実装範囲は `PRODUCTS.md` に記載しています。

## 平文の非干渉を形式モデルで証明する

`formal/Policy.lean` は認可判定に加え、出力する値を選ぶ情報流モデルを定義します。原文や秘密鍵を含む秘密状態、利用者が公開を許可した値、暗号文は別の入力です。

公開用の要求列と承認済みの値が同じなら、秘密状態と暗号文を差し替えても、クリップボードと共有ファイルへ出る平文の列は同じになります。この性質を、任意の長さの有限操作列についてLeanで証明しています。公開を許可する操作は、秘密情報の公開を例外として認める「機密解除」に当たります。利用者が公開を許可した値の中に機密が残っている場合、その機密まで隠す定理ではありません。

| 定理 | モデルで示す内容 |
| --- | --- |
| `denied_emits_nothing` | 認可を拒否した操作は、モデルのどの出力経路にも値を出さない |
| `plaintext_depends_only_on_release` | 外部向けの平文は、要求と公開を許可した値だけから決まる |
| `external_plaintext_noninterference` | 秘密状態を変えても、同じ許可済み平文の出力は変わらない |
| `trace_plaintext_noninterference` | 上記の性質が任意の長さの有限操作列について成り立つ |
| `only_approved_plaintext` | 平文出力は空、または公開を許可した値そのものに限られる |

既存の6つの認可定理と合わせて11定理を検査します。`sorryAx`、独自の公理、ネイティブ評価に依存する公理は許可しません。使用を認めるのはLeanの標準公理 `propext`、`Classical.choice`、`Quot.sound` です。[Lean公式の証明検査の説明](https://lean-lang.org/doc/reference/latest/ValidatingProofs/)も参照してください。

## JavaScriptとの対応を検査する

実際の出力も `src/information-flow.js` を通します。コピーと共有ファイルは `released`、暗号化下書きは `sealed`、端末内AIは `private` という別の入力を使います。拒否した場合は、値を読む前に停止します。

ビルドでは、4区分×4操作×5経路×32通りのフラグ、計2,560条件について、認可の可否と出力経路がそれぞれLeanモデルと一致することを確認します。承認後の版変更、非同期処理中の取り消し、秘密状態の差し替え、公開用の値以外を読まないことは自動テストでも検査します。

この有限領域の一致検査は、JavaScriptプログラム全体の形式検証ではありません。値の加工、承認のUI、非同期処理、暗号、DOM、ブラウザAPIの意味論までLeanへ変換した証明はありません。全ソースの構文検査は、別名やUnicode表記を含む既知の未登録I/Oを検出する保守用の検査であり、健全なJavaScript情報流解析器ではありません。

## 各経路の扱い

| 経路・観測 | 実装と残る前提 |
| --- | --- |
| 原文・候補・処理記録の画面表示 | 許可された端末利用者だけが見る領域です。DOM、拡張機能、開発者ツール、スクリーンショットによる読み取りを防ぐ証明はありません。 |
| クリップボード | 公開を許可した現行版だけを渡します。他アプリやOSによるクリップボードの読み取りは制御しません。 |
| 署名付き共有ファイル | 公開を許可した本文・条件・公開側の時刻・鍵を含みます。原文、置換表、原文ハッシュ、内部の編集回数、内部の承認用ハッシュは添付しません。承認した平文の安全性や受取人の再配布は保証しません。 |
| 下書き・暗号集計の交換ファイル | v2は1MiBの固定長フレームをAES-256-GCMで暗号化します。平文のUTF-8長はフレーム内部に置くため、ファイル長からその長さを区別する経路を減らします。暗号文そのものの機密性はAES-GCM、乱数、パスフレーズの秘密性などの暗号学的前提に依存し、Leanで証明していません。旧v1は読み込み互換のみで、固定長ではありません。 |
| ファイル名 | 固定の用途名または日付だけを許可します。任意の本文や識別子を名前に埋め込むことは許可しません。保存先フォルダの権限は検査しません。 |
| ローカルAI | 同意した現行版をループバックへ送る、許可された秘密情報の転送です。受信するOllama、モデル、ローカルプロセス、OSの名前解決とネットワーク処理を信頼します。そのプロセスが外部送信しないことの証明はありません。 |
| ZK・MPC・BFV・DP | それぞれの目的に応じて集計値・件数・証明・シェア・暗号文などを出します。厳密なゼロ漏洩とは異なります。公開する情報と方式の前提は `PRIVACY_COMPUTATION.md` に記載します。暗号プロトコル全体の安全性は今回の定理に含みません。 |
| アプリ・WASMの読み込み | 公開された静的ファイルを取得します。入力した文書を取得URLへ含めません。ホストにはアクセス元や取得時刻が見えます。ホスティング、配信内容、TLS、依存ライブラリは信頼する対象です。 |
| 未登録の通信・保存 | 認可モデルでは拒否します。既知の直接I/Oを構文検査で検出し、CSPでも接続先を制限します。これらを回避する任意の悪意あるJavaScriptを隔離する証明はありません。 |

暗号化ファイルでも、ファイルの存在、保存回数、操作時刻、処理時間、メモリ使用量、障害の発生は隠しません。原文を加工した時点で個人情報が完全に消えたと判定する証明もありません。

## ビルドごとの証拠を公開する

GitHub Actionsはテスト・Lean検査・出力経路の構文検査・ビルドを実行し、成功した版を公開します。`assurance/report.json` に定理名、公理、有限入力の検査件数、ソースとモデルのハッシュ、前提、未証明の範囲を記録します。`assurance.html` から検査対象と結果を確認できます。

この報告は電子署名付きの第三者認証やTEEのアテステーションではありません。サイト運営者が配布するコードと報告の対応を確認しやすくするための情報です。Leanのカーネル、検査スクリプト、ビルド環境、GitHub Actionsと配信先を信頼する必要があります。

端末全体を対象にする場合は、利用するOS・ブラウザ・端末の構成、攻撃者の権限、物理アクセスやサイドチャネルの扱いを先に定義する必要があります。[seL4の形式検証](https://sel4.systems/About/FAQ.html)のような検証済み基盤にも、ハードウェアやタイミングに関する前提があります。現在のGitHub Pages上のアプリだけで、その範囲の不在証明を完了したとは主張しません。

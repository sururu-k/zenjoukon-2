# Leanモデルを可視化する

お預かりした Lean4SemanticBench のビューアを使い、Sumi の２つの Lean モデルを別々に表示します。データは各モデルのソースをコピーし、Lean 4.34.1 でビルドして生成したスナップショットです。ブラウザで開いて宣言を選ぶと、その定義や依存先、参照先を確認できます。

- [認可・情報流モデル](policy/index.html)：初期表示は `Sumi.trace_plaintext_noninterference` です。
- [エージェント判定モデル](agent/index.html)：左の一覧から `execute_requires_*` を選ぶと、各条件に関する定理を表示できます。

グラフは**Leanの小さなモデルの宣言と依存関係**を表示します。JavaScript、ブラウザ、OSを含む全システムの安全性や、情報漏洩全体の不在を証明するものではありません。文書のゼロ知識証明のNoir回路は対象ではありません。

## 検査結果と限界

Leanのビルドは両方成功しました。Lean4SemanticBenchのレポート検査は、エージェント側が全項目通過、認可側は２項目で不合格です。認可側では自動生成された `splitter` ２件の位置情報がなく、対象188宣言のうち原文を表示できるのは173件でした。グラフと一部の原文は表示できますが、**全宣言の原文・位置が揃っていると見なせません**。詳細は各フォルダーの `check.log` を参照してください。ツールのチェックは、Leanの定理の正しさや実装との一致を新たに証明するものではありません。

ビューアは指定バージョンの p5.js と Tailwind を外部CDNから読み込みます。閲覧時にネットワーク接続が必要で、CDNにはアクセス元が見えます。入力文書を扱う画面ではありません。ブラウザから直接ローカルファイルを開いても動作します。

## 来歴と更新

元ツールはユーザー提供の `Lean4SemanticBench-main.zip`（SHA-256 `c7fa58186b4f3999952eea9253965a9a3be5137dbc997d208c3a986f7b1dfc3c`）。同梱の[MITライセンス](LICENSE)を保持しています。各 `report.meta.json` は一時Lakeプロジェクトで生成したためGitコミットIDを持たず、対象の実ファイルのハッシュは [manifest.json](manifest.json) に別途記録しています。複製した２モジュールには同名の `main` があるため、同時ロードせず別々に解析しました。

`node scripts/check-lean-visualization.mjs`（`sumi` ディレクトリで実行）は、元モデルと、レポート・埋め込みデータのハッシュが記録と一致するか確認します。モデルが変わった場合はZIPのツールでそれぞれ再生成し、チェック結果とハッシュを更新してください。ハッシュは真正性の署名ではありません。
